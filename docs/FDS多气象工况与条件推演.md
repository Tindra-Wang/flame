# FDS多气象工况与条件推演

2026-10-23。此页说明当前实际支持范围，不承诺任意场景、任意天气下的真实预测准确度。

## 当前入口

3D编辑器 → 渲染 → FDS三维场→Blender，选择晴/雨、温度、湿度、室外风速及求解时长。选多个天气时，每个天气分别进入FDS求解，不共用晴天物理场冒充雨天结果。最多8个独立工况，作业选择器按天气区分，MP4及物理时间轴仍在编辑页查看。

基础链路：已保存场景修订 → 自动网格/手动网格 → 生成各天气独立配置 → FDS求解 → 三维场/OpenVDB → Blender → MP4/候选帧 → 标注质检 → 审核 → 版本导出。

## 气象如何进入求解

- 温度：`MISC TMPA`；相对湿度：`MISC HUMIDITY`，单位%。湿度进入气相背景，不等于燃料含水率。
- 室外风：当前为既有单方向均匀边界风，支持风速；尚未接入风向控制、阵风/垂直大气剖面。
- 室内：采用几何开口和热浮力通风，不直接将室外风速赋为室内统一风速。尚未配置外部风压向建筑开口传递。
- 雨：`PART SPEC_ID='WATER VAPOR'`定义液态水滴，`INIT`从计算域顶层周期注入。质量流量`kg/s = 降雨mm/h × 顶部面积m² / 3600`；雨滴携带质量，参与FDS颗粒/气相过程。默认5mm/h、1000μm，支持0.1–50mm/h、100–3000μm；初始向下4m/s，单一直径及数值颗粒采样200个/0.2秒，是待标定近似。
- 屋顶会遮挡自顶部注入的雨滴。雨天室内与露天不应获得同样直接淋雨结果。

雨滴可进入FDS，不代表雨滴已经在Blender中可见：当前导出温度、烟炱和HRRPUV体积场，尚未导出FDS雨滴轨迹到渲染器。视觉雨雪合成仍在数据合成模块独立运行，并标注视觉增强来源。

当前火源为规定HRR等效燃烧器，未建立材料受潮后热解、雨水积聚、燃料含水率和真实熄灭模型。不能宣称已预测下雨后火势熄灭；需要材料/降水实验数据与物理校准。

## 雪和其他天气的边界

降雪需要雪粒/冰的传热、熔化、蒸发、沉积及燃料含水率耦合。当前没有该实现，API明确拒绝，不转用Mantaflow冒充FDS。雾/能见度、日照与雨雪画面合成也不等于物理气象建模。模板覆盖的是局部简化场景，不是所有建筑和大尺度林火模型。

要扩展到完整目标，应依次补充：室外风向/时变风及建筑开口风压；材料热解与含水率；粒径分布和雨淋抑制标定；雪相变/积雪；对每类天气做网格与颗粒敏感性及独立实验验证。公开资料不足以将它们直接标为完成。

## “预测”在页面中的含义

当前页面优先展示FDS在给定场景、火源和气象下计算出的下一求解时刻（`fds_next`），包含重心位置和最高温度来源。最后一帧明确显示本次推演已结束，可以延长时长重新运行。

这属于条件数值推演：从设定初始/边界条件计算未来。不是将摄像头观测输入已训练模型后的真实火势预测。既有三帧重心线性外推仍作为`forecast`基线保存在时序导出中，不再作为页面主要FDS预测展示。

训练数据仍是历史FDS帧→下一FDS帧。`fds_next`来自完整已算工况，仅作下一时刻展示/监督标签，严禁作为预测模型输入。训练JSON下载会移除fds_next展示字段，保留历史窗口及目标索引。派生图与同一工况分组划分，真实泛化需要独立数据。

## 接口与模块边界

- `fire_modeling/fds_weather.py`：物理气象校验、雨滴输入、条件记录；不依赖Web/数据库。
- `SceneConfig`：冻结每个工况温度、湿度、雨量/粒径及天气；旧配置默认40%湿度、无雨。
- `POST .../scene-editor/generate`：先校验全部组合，再创建独立作业；根幂等键派生各子键，重试不重复提交。返回首作业及`batch_jobs`。非数据库级全批事务；极端数据库故障后可用相同键补齐。
- `video.json`与候选manifest保留实际物理天气；`physical_conditions`写明液态近似及限制。
- 已有数据合成模块的rain/snow标记是视觉变化，不能混为新的FDS气象求解。

## 验证

晴/雨小网格均实际运行FDS到3秒，雨滴输入被求解器接受。覆盖相对湿度、降雨质量流量、非有限值、未支持雪的拒绝、独立工况快照和幂等重试。数值运行成功只证明输入链路，不证明雨天真实火势预测已校准。
