# ADR-001：以阶段产物契约组织火焰合成

日期：2026-10-23。

状态：采纳；新增受控合成链路已按此边界实现，旧任务入口保留兼容。ControlNet运行与真实数据效果评价尚未完成。

## 背景

现有FDS视频与样本合成有不同编排入口。基础渲染、生成增强、时序数据与标签用途容易混淆；按样本数量循环不能保证全部条件组合覆盖。项目要求保持页面清楚、模块高内聚低耦合，并控制本机资源成本。

## 决策

- 保留模块化FastAPI、PostgreSQL任务、独立Worker和现有Compose引擎，不新增大量微服务。
- 按编排、物理、渲染、增强、标注质量、数据集划分模块；以版本化产物清单交接。
- 原始物理分支与增强训练图分支共用来源，分别记录用途和标签策略。
- 显式规划场景/工况/天气/视角/时间/增强组合；物理天气变化与视觉天气变化分别处理。
- 物理、渲染及增强分别缓存和重试；应用层负责权限、持久化和阶段状态。
- 使用Diffusion实现生成增强。后续若替换模型，通过增强适配器接入，保持上游场契约不变。

## 取舍

收益：调整曝光或增强参数时复用FDS；切换模型时保留渲染与审核链；页面只呈现同一流程的状态和结果。

代价：需要明确清单模式、来源哈希、失败/部分成功规则，并渐进替换现有大循环；文件数量和存储成本需要预算。

未选择：让前端串行调用所有引擎；让SD模块直接改写FDS场或原始标签；一次性拆成独立服务和多套数据库。

## 实施与验证

以[火焰合成链路实现方案](../火焰合成链路实现方案.md)为实施蓝本。先完成组合和契约测试，再做基础渲染对照、受控增强验证及小批次端到端验收。真实数据泛化、光学校准和训练收益需独立证据。
