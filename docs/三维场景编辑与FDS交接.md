# 三维场景编辑与FDS交接

## 操作

在“仿真与合成”选择场景，点击“打开完整3D场景编辑器”。编辑页与主平台同源、共用账户，不依赖8765服务。

保留提供项目的SceneWorkstation：模型架及搜索/分组、GLB上传和拖放、物体位置与转向、燃烧物及起火开关、结构添加/移动/缩放、起火点、三种相机及位置/目标/焦距、灯光、气体域、视口着色与显示隐藏、快捷键、场景预设。

点击“保存场景”保存修订；“保存并进入仿真”返回原页面，自动选择同一场景。主页面设置FDS网格、时长、HRR、输出尺寸、采样、天气及SD开关，执行同一任务队列。

## 真实执行与边界

1. 场景以`config.editor_scene`随任务冻结，不在执行中读取后来修改的场景。保存时检查修订冲突，沿用项目权限。
2. FDS收到保存的结构、起火位置、模型的旋转外包围盒和起火标记。几何吸附到网格；预设起火面以保存起火点为准。显式勾选起火的物体分配总HRR预算，其余可燃物不自动热解或蔓延。燃烧物影响等效燃料烟炱参数；当前反应仍是丙烷替代模型，不是木材/塑料的实测热解模型。
3. FDS实际三维温度、烟炱、HRRPUV经浮点场契约和OpenVDB进入Blender。Blender使用保存的相机、灯光、结构及模型网格。FDS求解后模型哈希变化会拒绝渲染，不能静默换模型。
4. 可选SD增强、候选掩膜和框、质检、人工审核、DVC及COCO/YOLO沿用现有链路。编辑视口隐藏不影响真实求解或渲染。

原编辑器的Mantaflow气体域、预热、涡度和噪声控件保留用于场景记录；当前FDS链路不使用这些参数求解。FDS网格/时长、Blender采样由主页面控制；界面“链路与视角”页签明确说明，不能把保留控件当成已运行的第二套求解器。

五个可离线使用的模型是本项目生成的简模（沙发、木桌、盆栽、木箱、石块），非原Poly Haven等第三方资产。其他目录项因原源码未包含模型文件，以“燃料盒”明确显示；可上传GLB使用真实网格。单文件≤8MB、≤50000三角面，拒绝外部URI引用，上传记录和下载均按项目隔离。

## 走势与后续接口

主页面显示FDS→OpenVDB/Blender→SD→候选质检的实际任务状态。结果区显示已求解HRR时序；新三维场还记录HRRPUV加权燃烧区重心。它们是仿真时序，不是训练模型预测、不外推到求解时段外，也不代表真实蔓延精度合格。

后续AI趋势预测应增加独立模型/输入窗口/不确定性/评价记录，保留FDS基线，不用生成图像替代物理参照。

## 构建

`./scripts/build-scene-editor.ps1`复用已安装的原前端依赖，生成`web/public/scene-editor/`；`npm --prefix web run build`将编辑页一起打包到主平台。`start-platform.ps1`已包含编辑器构建。首次干净环境需可安装原前端锁定依赖，已有环境无需重复下载。

核心实现：`scene-editor/`、`platform_api/scene_editor.py`、`fire_modeling/editor_contract.py`、`fds_volume_scene.py`。原始FirePhantom目录和导入源码均未修改。
