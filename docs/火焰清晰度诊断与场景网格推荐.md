# 火焰清晰度与场景网格推荐

更新时间：2026-10-23。适用AI-07，接口与实际作业共用场景契约。

## 实际图像诊断

检查了室内原图 `6de9f0e8056f224d0e7020a5/render/images/raw_549818fbf08a1e2edcaa.png`：256像素、0.2米网格，发光区平滑，边缘细节不足。对应SD图增加纹理，但不代表CFD物理场更精细。

最近室外批次 `88d7040c585d7959d1dd9af5` 使用0.8米网格，图像还被大体积简化物体遮挡。问题同时涉及场景遮挡、物理分辨率和体积光学映射。扩大图片像素或提高渲染采样，不能补回求解时缺失的小尺度结构。

火焰是参与介质，边缘随温度、烟炱、热释放率、视线积分及曝光逐渐变化，并不应强制做成硬边。但当前平滑发光团也不能全部解释为真实火焰特征。当前映射未做辐射/相机响应标定；新增模板和网格推荐不等于已完成物理或视觉校准。

## 公开实现可参考什么

- [FDS / Smokeview 官方](https://pages.nist.gov/fds-smv/)与[代码](https://github.com/firemodels/fds)：低速火驱动流动、烟和热输运，重点是物理量、验证与网格敏感性，而不是单看视频是否逼真。
- [BFDS](https://github.com/firetools/bfds)：在Blender中构建和管理FDS模型，可参考几何建模与FDS输入组织；不能据此声称已有完整照片级场渲染。
- [FLAME_SD](https://github.com/AIS-Clemson/FLAME_SD)：掩膜引导的野火扩散合成，可参考区域控制与候选数据增强；它不替代CFD求解。
- [EmberGen](https://jangafx.com/software/embergen)：商业实时烟火视觉制作及OpenVDB导出示例，适合比较视觉表现，不能作为消防工程精度依据。
- [Fumaris](https://github.com/Michael-Venous/fumaris)：Blender预览/烘焙/体积交接参考；开源仓库是Python集成层，原生运行时需另行取得，不能作为完整免费求解器直接接入。

## 自动推荐规则

不是“室内固定0.1米，室外固定0.8米”。输入为当前未保存场景的域尺寸、火源大小、峰值HRR和环境温度；硬预算为120000个单网格单元、160000个体积采样节点。

1. 按照当前求解器将总HRR等分给主火源与勾选着火物体，用单个燃烧器HRR计算特征火径：`D* = [Q / (rho × cp × T × sqrt(g))]^(2/5)`，使用Q(kW)、rho=1.2 kg/m³、cp=1.0 kJ/(kg·K)、T(K)。这些环境近似值和预算属于当前项目配置，不是全场景物理常数。
2. 项目初筛目标取 `dx <= min(D*/4, 火源最短边/4)`。数字4只是本项目低成本起点，不是FDS官方通用合格线。
3. 验证候选网格能否绑定完整场景、是否满足单元和节点预算，优先不改变计算域尺寸的网格。
4. 达到初筛目标时，选其中最粗的网格节约开销；达不到时给出预算内较细预览网格，并明确标注“解析度不足”。
5. 显示薄结构、小火源对齐和计算域取整风险。保留手动选择。手动模式仍接受已有资源上限校验。

[NIST FDS用户指南](https://raw.githubusercontent.com/firemodels/fds/master/Manuals/FDS_User_Guide/FDS_User_Guide.tex)要求针对关注量逐步细化做敏感性研究，明确不存在可直接套用的通用最低D*/dx。当前推荐不自动完成收敛研究，也未实施多网格局部加密。

## 页面和接口

3D编辑器 → “渲染” → FDS三维场 → Blender → FDS网格尺寸默认“自动推荐”。修改域、场景和环境温度会重新计算。推荐还展示D*/dx、网格数量及预算不足提示。

`POST /api/projects/{project}/scene-editor/grid-recommendation`

请求：`{scene_id, editor_scene, temperature}`。场景归属必须属于当前项目；editor_scene可为未保存编辑草稿。只返回建议，不修改数据库场景。

`POST /api/projects/{project}/scene-editor/generate`

生成参数携带 `mesh_policy: auto`。提交时服务端使用已保存场景重新计算实际dx，不信任浏览器传入的推荐值。作业payload保留mesh_recommendation、generation和实际config，以便追溯。`manual`模式保留指定dx。

链路为：场景草稿 → 推荐预览 → 保存场景修订 → 服务端重新推荐 → 冻结作业配置 → FDS求解 → 三维温度/烟炱/HRRPUV → OpenVDB → Blender → MP4及候选帧 → 受控SD增强 → 自动标注/筛选 → 人工审核 → 版本化导出与真实数据评价。

推荐函数仅依赖场景契约，不依赖Web、数据库或渲染器；API负责项目权限和快照；前端仅显示结果。网格改变后必须重新求解，不复用旧网格的物理场冒充新结果。

## 新增模板

从编辑器顶部“从模板新建”创建独立场景，不覆盖已有场景。提供家具房间、走廊、仓储、灌木场地、木堆场地、工业场地六种几何。不同模板具有不同计算域、开口、障碍与相机设置；同一份数据进入FDS和Blender。

模板为自建简化几何和规定HRR等效火源。燃烧物会影响现有等效参数，但不代表真实材料热解、蔓延或储罐爆炸已标定；目前不应用于工程安全结论。

## 如何避免成本失控

先缩小到关注的局部场景，再选更细网格。网格尺寸减半时单元数约增为8倍，时间步限制还会增加总计算时间。不要一开始把40×40×20米场地全部换成0.1米网格。模板仅做局部域示例；扩展到整栋建筑/大林区需要更高预算、分域或局部加密及独立验证。

真实数据相似度与下游检测收益仍需独立真实数据集、人工审核及固定测试集，不能以网格推荐或照片更好看替代验收。

实测：新家具房间模板0.1米网格、72000单元，FDS实际求解覆盖6秒，Blender渲染4个时刻并完成MP4。作业 `36c82a85b851a6aa86a87346`。最终帧火焰可见，但体积边缘仍平滑；尚未证明光学真实性或网格收敛。6秒/4帧仅是链路验证预算，模板保存时长12秒，页面作业默认20秒；不是建议用4帧训练时序预测。
