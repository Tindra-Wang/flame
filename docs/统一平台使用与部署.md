# AI-07 统一可视化平台

平台入口：**http://localhost:3000**。API：**http://localhost:8092/docs**。独立Label Studio：**http://localhost:8082**；原有8080服务保留。完整工具（8082）用独立服务账号登录：用户名 `ai07-service@localhost`，密码在 `.cache/platform/compose.env` 的 `AI07_LS_PASSWORD`；页内审核只需平台登录，不依赖该账号，Label Studio 服务令牌不会进入浏览器。

## 启动

在项目目录执行：

```powershell
cd D:\软件工程\AI-07
uv pip install --python .venv/Scripts/python.exe -e ".[web,test]"
powershell -File scripts/start-platform.ps1
```

首次运行自动生成`.cache/platform/compose.env`中的服务凭据，**不要提交到Git或截图公开**。浏览器先可只读查看实际候选图；点击“创建工作区账户”，自行设置用户名和至少10位密码。首位用户为产品经理，可在“工程与验收”创建架构师、开发工程师、测试师、运维师。没有共享的默认平台密码。

Compose使用PostgreSQL、FastAPI、Vue/Nginx、专用Label Studio。现有FDS、Blender、SD镜像通过原compose.yaml复用。本机独立Worker主动访问8092领取任务；API容器没有Docker socket，不获得主机Docker控制权。工作进程日志在`.cache/platform/worker-compose.*.log`。重复启动前确认没有重复Worker进程；每个任务通过租约领取，当前建议仅启动1个GPU工作进程。

只发布到127.0.0.1。当前是本地研究部署；没有完成公网TLS、云端可用性、跨主机备份和最终安全验收，不可把本机入口当作云端交付。

## 完整操作路径

1. **场景与生成**：选择室内/室外，设置HRR、网格、时长、种子、分辨率、双视角。默认2张先验证。物理路线实际执行FDS → Blender → SD；程序预览仅检查流程，不冒充物理仿真。
2. **任务中心**：查看逐阶段日志、错误及产物；支持取消和重试。工作进程离线时真实保留排队状态，不自动造成功结果。当前单任务最长2小时，交互批次≤100张、≤768像素、FDS时长≤60秒；扩大资源需另行验证。
3. **样本与标注**：来源/批次/审核状态检索；点击样本修订框，支持拖动和键盘新增/数值坐标编辑。增强图可与父图并排对比。空框用于无火；未审核候选不进入版本。
4. **Label Studio**：Compose集成已通过专用服务账户配置。选择批次后“同步到Label Studio”，再在服务中人工标注；“导入已完成人工标签”只接受人工annotation，不把prediction当人工审核。当前已同步的批次记录外部项目ID；不会自动持续同步后续人工编辑，需显式再次导入。管理界面登录凭据由`.cache/platform/compose.env`中的AI07_LS_PASSWORD给出，用户名ai07-service@localhost；不要共享后端服务令牌给普通前端。
5. **版本与导出**：仅人工通过且结构/哈希合法的样本纳入研究快照。DVC add → Git commit → DVC push → 本地备份清单核验成功后才允许下载。失败版本不可下载，旧版本不可覆盖。COCO类别fire=1，YOLO类别fire=0。少量独立源组可能造成空验证/测试集合，不为凑数拆分同源图像。
6. **效果评价**：可导入独立物理参照与预测，或COCO人工真值及预测，实际计算指标。FID需先导入有来源和许可的真实批次，再与合成批次对照；当前使用Inception 64维特征并记录维度，少量图像仅作流程诊断。没有真实数据不填写虚假FID、mAP提升或物理误差。完整YOLO等预算对照仍可通过已有`train-yolo-pair`命令运行，详见原Compose建模指南，不能把指标上传计算当成完成了训练收益验收。
7. **工程与验收**：查看六项技术、功能落点、SRS阈值、实际证据、测试报告、文档和缺失交付物。PPT/视频、独立视觉评价、7天可用性和云端部署没有证据时均保持未提交/待证据。
8. **参考与架构**：查看已核验的GitHub仓库、借鉴边界、架构与ER。24表ER是完整目标设计；当前平台采用独立web_前缀表和已有文件清单，未直接应用schema.design.sql，不混淆目标DDL与运行数据库。

## 真实数据导入

上传ZIP≤50MB，解压≤150MB，包含`coco.json`及`images/`目录。COCO中file_name相对images目录，类别id=1/name=fire，像素xywh。填写来源链接和授权说明；每张图可提供group_id，否则整个导入视为一个源组以避免未知来源泄漏。上传接口拒绝路径穿越和加密压缩包。即使导入已有框，也必须人工确认后发布。

## 工程运行

```powershell
# 可选轻量监控
docker compose --env-file .cache/platform/compose.env -f compose.yaml -f compose.platform.yaml --profile monitoring up -d prometheus grafana
# SonarQube按需运行，约需额外内存；自行初始化令牌后扫描
docker compose --env-file .cache/platform/compose.env -f compose.yaml -f compose.platform.yaml --profile quality up -d sonarqube
# 实际测试与覆盖率
.\.venv\Scripts\python.exe -m pytest -q --basetemp=.cache/manual-test --cov=fire_modeling --cov=platform_api --cov-fail-under=70 --cov-report=xml:artifacts/platform/coverage.xml
```

Prometheus入口9090，Grafana入口3001，SonarQube入口9000。Prometheus读取真实`/metrics`，告警规则包含API不可用与失败任务；只有配置Alertmanager/外部接收端后才会向外推送通知，当前不发送消息。Grafana用户名ai07，密码在本地compose.env中。Sonar和外部通知未运行时不得宣称质量门禁、告警闭环已验收。

GitHub Actions工作流提供Python测试/覆盖率、Vue类型检查/构建，Sonar扫描需仓库配置SONAR_HOST_URL和SONAR_TOKEN。当前本地测试报告不等于远端CI已经运行。

## 备份与恢复

数据库：使用`pg_dump -U ai07 ai07`导出，恢复到独立数据库先做演练；产物卷与`.cache/platform/dvc-repository`、`.cache/platform/dvc-backup`、服务env需一并保管。不要使用`docker compose down -v`作为停止命令，否则会删除数据库卷。

DVC备份和清单校验当前在同一台机器上，不能抵御整机损坏。正式交付前应迁移remote至独立磁盘/SSH/S3并验证恢复，保留恢复记录。失败的发布保留staging/failed状态，重试使用新版本名；已发布版本不就地修改。

## 边界

已有实跑候选图较粗糙，生成成功、结构通过均不是视觉质量/物理5%/检测提升15%的证据。当前没有真实标注数据及独立物理参照；相应验收保持待证据。成本仅记录人时、用量与公式，不填具体金额。
