# 真实数据导入与价值验证

本课题的价值重点：用可控合成补充真实火焰数据覆盖，并通过候选标注修订降低人工成本。两个结论均需真实证据，生成图片数量不能直接作为价值成绩。

## 当前如何导入（COCO ZIP 或 数据集链接，二选一）

入口：登录主平台，进入“样本与标注→导入真实数据”。产品经理、架构师、开发工程师、测试师可导入。

- **方式A 上传 COCO ZIP**：压缩包根目录包含`coco.json`与`images/`，不要多套一层文件夹；必须填写原始来源链接和授权/许可证说明。单次≤50MB，解压≤150MB、≤3000条。
- **方式B 粘贴数据集链接**：只填链接即可导入，授权可留空（登记为“未登记授权”，发布版本前应补齐）。figshare/机构 figshare 的**文章页链接**会自动经公开 API 解析出 ZIP 下载地址——例如直接粘贴 CQU 数据集页面链接即可；普通 `.zip` 直链则直接下载。远端包≤800MB流式下载；平台按“有火焰框优先、确定性顺序”抽样解包到导入上限内，并把抽样数量写入导入审计记录。指向内网/本机地址的链接一律拒绝（SSRF防护）。
- 两种方式导入后流程相同：选择该真实批次 → 执行质检 → 页内修订/审核；导入标签不会自动变成人工通过。分布评价选审核后的真实批次；检测对照需先发布真实数据DVC版本，并确保train/val/test均非空且来源独立。

目录示例：

```text
real-fire.zip
├── coco.json
└── images/
    ├── fire001.jpg
    └── negative001.jpg
```

下面仅是单图格式示例，不是可运行实验数据：

```json
{
  "images": [
    {"id": 1, "file_name": "fire001.jpg", "width": 1280, "height": 720,
     "group_id": "event001"}
  ],
  "annotations": [
    {"id": 1, "image_id": 1, "category_id": 1,
     "bbox": [300, 220, 180, 260], "iscrowd": 0}
  ],
  "categories": [{"id": 1, "name": "fire"}]
}
```

`file_name`相对于`images/`，图片尺寸必须与文件一致；bbox为像素`[左上角x, 左上角y, 宽, 高]`，不是右下角坐标。当前支持单类`fire`，类别ID为1，不支持crowd/旋转框。

`group_id`应优先使用真实火灾事件ID；同一事件的不同机位、视频和相邻帧应保持同组。缺少group_id时，整次导入保守地视为一个来源组。同一事件拆包导入仍需统一核查来源，当前跨导入的事件标识会带批次命名空间，不能只靠哈希检查识别相邻帧泄漏。

只有图片时也可整理images元数据并使用空annotations导入，再逐张添加火焰框。此时是待标注数据；只有人工确认无火后才能将空标签审核通过。当前没有“任意照片ZIP自动识别并预标注”的入口。FID不需要框，但当前统一流程仍要求审核图像与来源；火焰ROI评价及检测训练需要可靠标签。

当前导入保留来源、授权、文件哈希及group_id；尚未完整保留真实图像的天气/场景等自定义COCO元数据。后续分层覆盖与分层评价需先补统一条件字段。当前按来源组确定性划分数据集，少量组可能导致空集合；不应拆开同一事件来强行填满集合。

## 价值一：补充真实数据稀缺与覆盖不足

真实样本登记与审核 → 建立可用真实基线 → 识别缺少的场景/天气/视角/火焰尺度 → 定向配置FDS工况和生成组合 → 自动候选标注与质检 → 人工复核 → 版本化合成补充集。

应记录审核可用数量、独立工况数、条件覆盖和拒绝原因，区分源工况与其渲染/扩散派生。重复帧、重复图片和同一工况的多个变体不作为独立火灾事件计数。

再分两层验证：

- 图像层：固定真实参照，分别比较基础渲染与增强图的分布；FID/颜色JS为不同指标，不能混称。当前支持整体及原图/增强范围选择，尚未自动分层或做ROI评价。
- 任务层：A仅真实训练，B同一真实训练集加合成集，在相同真实测试集上比较检测指标。记录数据版本、权重、种子与训练更新预算；提升可能为负。最终测试集不用于反复选择生成参数。

若要进一步证明“减少真实数据需求”，需增加真实训练样本量的分档实验，在相同测试集上观察加入合成数据能否以更少真实训练样本达到可比较的检测表现；目前此分档实验尚未实现。

## 价值二：降低标注成本

对同一批待标注图像做两种方式：A从空框人工标注，B自动候选框加人工修订。采用可比较样本与交叉分配，控制图片难度、审核规则及重复看图的熟悉效应。

记录每张图的有效操作时长、返修时长、审核结果及候选框修改情况。以“最终审核合格样本”为分母：

`人工分钟/合格样本 =（标注＋复核＋返修的有效人工分钟）/ 最终合格样本数`

`人工工时节省率 =（A组每合格样本工时－B组每合格样本工时）/ A组每合格样本工时`

自动化运行时间、GPU资源与人工工时分开统计，再按项目需要折算总成本；不预填金额。候选通过率、标注IoU和抽检返修率同时报告，避免通过放宽审核来制造省时。

目前已有候选框、页内审核、审核人/时间戳/修订、Label Studio同步和版本门禁；尚未实现有效人工操作计时与从零标注的工时对照。单个保存时间戳不能推算标注耗时，Label Studio服务端推送记录也不能当作真实人工耗时。

## 平台应优先呈现的价值证据

沿用现有栏目：样本页显示有效产出与审核情况，效果评价页显示分布与检测A/B结果。下一步补标注任务计时和成本对照，再将这些实际记录汇总到工程与验收页：

- 覆盖：哪些条件已补齐，多少独立来源、多少审核可用样本。
- 省工：从零标注与预标注修订的每合格样本人工时间及返修情况。
- 有效：真实测试集上的检测指标、差值及失败案例。
- 可复现：上述结论所对应的数据版本、审核记录、生成配置、模型和实验记录。

当前真实数据批次为0，尚无实际标注省时率、真实分布成绩或检测提升结论。下一步优先级是：导入真实小批量 → 人工审核与来源分组 → 补计时记录 → 固定版本的分布/检测对照，而不是继续堆积展示图片。


## 价值证据链实测记录（2026-10-25）

全链路经 `scripts/value_chain.py`（可复用命令行工具：convert/register/import/approve/version/ab/status 七个子命令，全部走公开 REST API）完成首次端到端实测：

- **真实数据**：CQU Annotated Fire-Smoke Dataset（figshare 存缴项 CC BY 4.0，内部为 Roboflow 导出且其 README 标注 license undefined，已如实登记披露）。采样 1250 张（含 fire 框 900 + 负例 350，576px/JPEG70，group_id 按来源序号聚类防泄漏）→ 导入 → 人工确认采信公开标注（审计留痕）→ 驳回 2 张跨 split 完全重复 → **V_real v1.3.0-real-cqu（1248 张：train 878 / val 190 / test 180）**。
- **合成数据**：v1.0.2-syn-fds（双场景双天气双机位受控合成，16 张扩散增强 + 8 张 FDS 体积渲染，train 12 / test 12）。注：v1.0.1-syn-ai07（原版 Mantaflow 128 张）被收益实验门禁正确拦截——来源标签 original_mantaflow_not_fds 不在允许集合（fds_openvdb_volume/diffusion/blender）内。
- **A/B 检测对照**（yolo11n，5 epochs，batch 4，384px，seed 42，GPU，两组各 1115 次训练更新，泄漏哈希检查通过）：
  - A 组（仅真实 878 张）：mAP50 29.21%，mAP50-95 13.13%，Precision 39.02%，Recall 33.33%
  - B 组（真实 878 + 合成 12 张）：mAP50 30.48%，mAP50-95 14.05%，Precision 40.25%，Recall 33.33%
  - **ΔmAP50 = +1.27 个百分点（相对提升 +4.34%）；ΔPrecision = +1.23pp；ΔRecall = 0**
- **边界（如实）**：单种子单次运行、合成仅 12 张训练图、5 epochs 小规模——不构成稳定收益结论，需多种子与更大合成量重复验证；页面保留"单次运行不代表稳定收益"注记。
- **标注计时**：审核接口新增 timing 字段（mode=scratch/candidate，active_s 有效操作秒数，>15s 无操作自动暂停），`GET /api/projects/{p}/timing` 聚合；效果评价页新增"标注成本对照"卡。从零 vs 候选修订的工时对照需后续人工标注实验积累数据。
- **工程修复**：版本发布状态改用独立会话＋局部 id 落库（长发布客户端断开不再卡 staging）；nginx /api 超时 300s→1200s；DVC 发布对 1248 张图实测约 6 分钟。

- **分布相似度（补充实测）**：FID-64 = 32.88（真实 1248 张 ↔ 合成 24 张，原图＋增强图，冻结快照与哈希）。判读：数值越低越接近真实分布；当前合成样本量小（24 张），此值仅完成流程验证，不构成"分布已足够接近"的结论。页面以白话结论卡展示。
- **评价页重设计（2026-10-25）**：按"实验台"心智重做——开篇一句话问题（合成的数据到底有没有用？），三个实验卡改白话命名（①长得像吗·分布 ②变强了吗·检测 ③准不准·物理），结论先行（大字判定卡：有效/下降/FID 值），参数收纳进"高级参数"，禁用状态必给原因与下一步指引，指标附白话解释（如 Precision=报"有火"时真是火的比例）。
