# 原版3D编辑器迁移与执行链路

更新：编辑器默认FDS，新增页内MP4/时序参数/因果外推与训练清单；当前操作及物理/增强边界以[FDS时序与训练数据链路](FDS时序与训练数据链路.md)为准。

这次直接复用原版`GenerationSettings`、`SceneRuns`、`JobDetail`、`ComboDrawer`以及`SceneWorkstation`。构建阶段导出原组件，未修改FirePhantom源文件。原先自行增加的底部作业面板、独立播放器和重复输出机位选择器已移除。

## 页面如何操作

编辑页顶部“开始作业”直接提交，未保存场景先保存；提交后留在本页“作业”查看进度与结果，不必进入任务中心。需要认证时页内登录，保留当前参数。“渲染设置”只负责调整参数。

任务中心作为跨场景管理入口：每页8条，支持搜索和状态筛选；详情优先显示执行阶段、MP4、样本审核及取消/重试，完整日志默认折叠。旧任务记录保留。

- 物体/场景：保留原版模型、燃烧物、起火点、结构、气体域、灯光、相机、变换、快捷键及视口操作。
- 渲染：保留风速、温度、湿度、晴雨雪、多机位、每机位帧数、噪声/模糊/光照增强、种子、火焰占比、重复烘焙、风速步进及生成预设。
- 作业：保留场景作业切换、组合进度、取消、整批重跑、分组重跑、帧/掩码/框/视频查看、选帧和全部送审。
- 待审核样本共用主平台Run；通过主平台标注质检、Label Studio与版本导出入口继续操作。送审不等同于人工批准。

## 两条明确的执行路线

### 原版 Blender / Mantaflow

保存场景修订 → 主平台入队 → Compose启动Blender → 运行原版生成的场景脚本 → 每个天气烘焙一次 → 多机位逐帧RGB/火焰、烟、余烬掩码 → 派生增强 → 每个组合MP4 → 同批候选样本与质检 → 选帧送审 → 人工标注审核 → DVC版本/导出。

原版的湿度、天气、燃烧物、气体域、预热、涡度等进入原版脚本。这是Mantaflow视觉模拟，不标记为FDS，也不宣称经过真实火灾校准。

烘焙次数＝重复次数×天气数；原始图数＝烘焙次数×机位数×每机位帧数；含派生图数量再乘以（1＋增强种类数）。一份烘焙由多个机位共用。视频编码位于渲染之后，不再次求解火焰。

### FDS三维场 → Blender

保存场景修订 → FDS几何/起火面/等效燃料 → FDS求解 → 温度/烟炱/HRRPUV三维场 → OpenVDB → 按固定机位、真实求解时刻渲染 → 每机位MP4及同一批候选帧 → 选帧送审/主平台后续处理。

帧数会控制求解输出采样与最终视频帧数量。12fps是编码帧率，求解帧间保持最近帧，没有AI补帧。FDS路线当前明确限制晴天、单次求解；雨雪、重复烘焙和传统派生增强组合选择原版路线，超出支持时明确拒绝，不静默丢弃。湿度/雨雪不是已标定CFD燃烧模型。SD生成增强仍是主平台的独立后处理阶段。

## 为什么之前一直不结束

用户任务`2898f7e747677d87d4e0668f`的FDS已结束；侧视6帧、俯视6帧、第一人称3帧输出后，工作进程中断。2026-10-23检查时Docker也未运行。证据支持“执行器中断”，不能断言具体由谁关闭服务。

旧FDS视频实现逐帧启动Blender、按机位串行渲染，又没有帧级状态，容易看起来一直在生成。此次修复：

- 持久化真实完成帧、总帧数、机位、阶段与耗时。
- 检查执行器心跳，离线明确提示；90秒无运行心跳转中断。
- 视频重跑复用原FDS结果及通过配置/来源校验的完成帧，避免全部重算。
- 交互作业30分钟上限；原版烘焙和编码还各有子进程上限。超时、取消或中断不会显示成功。
- 原版Mantaflow按原版方式在同一次Blender执行中烘焙并渲染多个帧/机位。

## 接口与模块边界

- 主场景：`PUT /api/projects/{project}/scenes/{id}`，修订冲突检查和项目模型隔离。
- 原版渲染入口：`POST /api/projects/{project}/scene-editor/generate`。
- 原版组件兼容口：`.../scene-editor/compat/jobs`、`jobs/{id}/stages`、`samples/{alias}`、`review-queue`；共用主平台账户、Job、Run，不另建上游平台数据库。
- 算法适配：`fire_modeling/original_editor.py`执行原版脚本；`video.py`处理FDS逐时刻渲染、进度、续跑与视频/候选帧交接；Worker负责串行调度和进程预算。
- 显示成功必须存在完整图像/掩码/视频和清单；不允许图片回退冒充物理渲染。
